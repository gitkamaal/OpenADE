# OpenADE work-machine handoff audit prompt

Audit the current `feature/zeron-parity` branch of OpenADE for a reliable local-only handoff to another Mac. Read `AGENTS.md`, the project brief, `docs/zeron-feature-map.md`, and the visual contract at the top of `docs/appearance-interaction-audit.md` first. The accepted native visual checkpoint is the September 28 **OpenADE UI Baseline QA** build; its synthetic profile/provider are test fixtures, not handoff configuration. The September 27 9:07 AM native recording is the older visual reference. Keep OpenADE's five-icon rail, header, compact chat composer, Frosted/Liquid/Opaque materials, and sliding right workspace/files panels. Do not redesign the shell while optimizing it.

Inspect the Go daemon, Wails bridge, React/WebKit client, provider adapters, persistence, streams, terminals, editor/browser lifecycle, and packaging. Prioritize actual correctness and resource problems: orphan processes and PTYs, subscriber/goroutine/socket leaks, unbounded queues or logs, unnecessary polling and renders, cold start, idle CPU/RSS, active-chat latency, sidebar/panel animation, editor/terminal memory, restart/reconnect behavior, and per-profile isolation. Check Claude Code and Copilot CLI code paths using synthetic providers where live accounts are unavailable. Preserve working streaming, thinking-step disclosure, questions, custom dropdowns, keyboard/focus/accessibility behavior, themes, and local project data.

Use a repeatable workload for before/after measurements on the same machine: idle window, one active streamed chat, 24-session history, long transcript, editor with 6,000 lines, terminal, browser tab, and repeated open/close/resize. Record p50/p95 cold and warm readiness, first visible stream, input-to-two-frames, session switch, native frame/GPU timing where tools allow, CPU, RSS, retained renderer heap, goroutines, file descriptors, sockets, and daemon subscriber count. State precisely which numbers are Chromium fixtures, native OpenADE, and matched Zeron measurements; never present one as another. Inspect the running native app over a contrasting desktop and compare it with the visual contract after each UI-affecting change.

Implement the highest-value safe fixes, add end-to-end coverage for observed failure modes, run relevant static/build and full affected suites, build a universal arm64/x86_64 app, and verify its signature and ZIP integrity. Keep screenshots, videos, profiles and performance traces local. Update the existing draft PR with tested changes; do not merge. Report concrete before/after scores, architectural changes, work-machine prerequisites, any unverified Intel/older-macOS behavior, and remaining mapped parity gaps. If an improvement would change the accepted visual baseline, document the tradeoff and leave it out of the handoff build until reviewed.
